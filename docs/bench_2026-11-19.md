# VLM benchmark 1 (2026-11-19)

Set: `python -m vlmbaseline.bench.build_set data/library_merged data/lab_03` (seed 0, up to 4 objects per label,
best keyframe view; 129 views, 23 excluded by eye where the export box / label was wrong -> 106 scored; 40 scene questions).
Run: `python -m vlmbaseline.bench.run <model>` (bitsandbytes 4-bit nf4, greedy, thinking off), score: `python -m vlmbaseline.bench.score`.
GPU RTX 3080 Ti Laptop 16 GB.

|---|---|---|---|---|---|---|---|---|
| Molmo2-8B (4bit) | 65% (69/106) | 64% / 66% | 100% | 100% | 22% (42% / 33% / 0% / 0%) | 0.769 / 2.348 / 3.056 | 7.13 | 13.5 |
| Qwen3.5-9B (4bit) | 74% (78/106) | 82% / 67% | 100% | 100% | 22% (33% / 25% / 8% / 25%) | 0.514 / 2.642 / 2.503 | 8.14 | 15.6 |
| gemma-4-12B-it (4bit) | 55% (58/106) | 64% / 48% | 100% | 100% | 28% (42% / 33% / 8% / 25%) | 0.447 / 3.474 / 5.266 | 9.4 | 16.0 |

- recog: red box on the keyframe -> English name, correct if it matches the reviewed label or a synonym / parent class.
- describe: Korean JSON (name, colour, material, state, uses); all three always return valid JSON in Korean. Content not scored.
- scene QA: object table (symbol, label, centre, size) as text + Korean question; counts, nearest, distance, largest / highest.

Findings
- Recognition: Qwen3.5-9B best (74%), Molmo2-8B 65%, Gemma-4-12B 55% (Gemma often names a different object than the boxed one).
- Common misses: orange cone-shaped sign stands ("orange cone"), small wall items (sticky notes, image signs, screens).
- Scene QA from a text table is poor for all (22-28%; distances ~0-8%): spatial facts must come from code over the graph
  (counting, distances, nearest, paths), with the VLM choosing the query and phrasing the answer.
- Speed and memory are fine for offline augmentation: 0.4-0.8 s per name, 2.3-3.5 s per description, 7-9.4 GB.

(count, find, object_info, nearest, distance, extreme, route, guide_to; walking distances over the 2D places)
and answers in Korean from the tool results.

|---|---|---|
| structured 40 (counts, nearest, distance, largest / highest) | 22% | **100% (40/40)** |

- Median 2.9 s per question (1-3 tool calls).
- The one miss: '안내판' mapped to label `sign` instead of `sign stand` (label wording, not reasoning).

## Bench 3: object descriptions and free-text search

Augmentation: `python -m vlmbaseline.augment.describe_objects data/library_merged data/lab_03` (Qwen3.5-9B 4-bit,
2 best views per object, reviewed label as a hint): 230/234 objects described (4 without a usable view), 3.3-3.6 s each.
The VLM disagreed with the label for 6 (library) + 17 (lab_03) objects; most overlap the boxes found wrong by eye in
bench 1 (e.g. lab_03 O430 printer = room number plate, O371 refrigerator = boxes, O435 monitor = thermostat).

Search (`python -m vlmbaseline.spatial.bench_search --agent Qwen/Qwen3.5-9B`), 25 everyday Korean queries
(e.g. '앉아서 쉴 수 있는 곳', '음식을 데우는 기계'), hit = the object's label is one of the acceptable ones:

| Method | top-1 | top-3 |
|---|---|---|
| SigLIP2 image-text only | 16/25 | 19/25 |
| VLM description words only | 15/25 | 18/25 |
| both | 17/25 | 20/25 |

Two of the agent's 3 misses are test-set errors (no orange sign in lab_03; the lab 'shelf' holds no books); the third

## Bench 4: states, grounding, task suggestions

Descriptions redone with a per-label list of visible states (e.g. 화분: 건강함 / 잎이 시들거나 누렇게 변함; 쓰레기통:
비어 있음 / 여유 있음 / 거의 가득 참 / 넘침) plus 점검_필요 and its reason; written into the graph as
`metadata.vlm` (`augment/write_dsg.py`, loads in spark_dsg with the mesh). Which states call for work is decided in
code (`tools.ACTIONS`); the `inventory` tool returns only those objects with the action.

Agent changes: when the model is about to answer without any tool call, that turn is forced to start with a tool
call; answers citing an object symbol that is not in the scene are sent back once; no example symbol in the prompt
(the model copied it).

## Bench 5: guidance from the user's pose (2026-11-20)

The user's position and heading (x, y, yaw) can be given to the agent (`Agent.ask(q, pose=...)`); keyframe camera
poses stand in for the user here (8 per scene). Two tools exist only then:

- `guide_me(label | goal)`: nearest object by walking distance; turn-by-turn steps relative to the heading
  (직진 / 왼쪽·오른쪽으로 비스듬히 / 돌기 / 뒤로 돌기, walk m, up to 2 objects passed per step with their side),
  where the goal is now and at arrival. The place path is simplified (Douglas-Peucker 0.6 m, legs < 0.8 m and bends
  < 40° removed) so a corridor is one leg.
- `around_me(label, side)`: objects within 4 m with direction (앞, 왼쪽 앞, ..., 뒤), clock direction and distance;
  `side` filters in code.

Left / right is checked against the cameras: objects in view project to the image side that matches the computed
direction in 13521 / 13521 cases (`tests/test_nav.py`).

Agent guards: route / guide_to only start from an object symbol the user named (otherwise the tool returns an error
telling the model to ask where the user is); a guidance answer without the goal symbol is sent back once.

| Test (Qwen3.5-9B, 4-bit) | Before guards | After |
|---|---|---|
| '여기서 가장 가까운 X까지 어떻게 가?' (goal, first turn, guide_me used) | 14/16 | 15/16 (the miss: '안내판' taken as `sign`, a correct route to the nearest sign; the set expects `sign stand`) |
| '내 앞 / 왼쪽 / 오른쪽에 뭐가 있어?' (first object cited is on that side) | 9/11 | 11/11 |
| same guidance question with no pose | 0/4 (invented a start object) | 4/4 ask where the user is (scorer fixed afterwards to not count the blocked call) |
| bench 2 QA again (structured / natural) | 40/40, 31/32 | 40/40, 31/32 |
| bench 4 unanswerable again | 15/16 | 15/16 |
